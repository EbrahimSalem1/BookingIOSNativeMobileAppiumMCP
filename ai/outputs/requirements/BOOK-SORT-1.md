> **Generated by:** Claude (requirement-analyst agent) from prompt `ai/prompts/01-requirement-analysis.md`

## 1. Understanding
Travellers re-order the current result set by price (ascending / descending), rating, or the app's
"Recommended" ranking, so that the most relevant stays for them appear first.

**Explicit rules:** options reachable from results; selecting one re-orders current results; active option visible.

**Implicit rules (inferred - need confirmation):**
- Price ordering is numeric and uses the *same price the card displays* (per night vs total stay).
- Items without a price (sold out) or without a rating are placed last.
- Sorting applies to the *filtered* set and does not clear active filters.
- The chosen sort persists when returning from a details screen.
- Infinite scroll pages loaded later respect the same order (order is global, not per page).

## 2. Open questions for the PO
1. Is the sort key the nightly price or the total stay price (incl. taxes/fees)?
2. Tie-break for equal prices/ratings?
3. Where do unpriced / unrated properties go? (Assumed: last.)
4. Does sort persist across new searches or reset to Recommended?
5. Are sponsored results exempt from sorting? If yes, how are they marked for the user (and for automation)?

**[REVIEW]** Q1 and Q5 are release-blocking for test design: they decide whether a sort failure is a bug.
Taken to the PO; until answered, the oracle uses the displayed card price and assumes no sponsored exemption.
